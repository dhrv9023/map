Phase A • P0 Essential

System Design Fundamentals

Duration: 3 Weeks • ~45 Hours

Why it matters: Before designing distributed GPU clusters, you must master the fundamental building blocks of scalable computing. In AI systems, these same primitives govern inference gateways, model artifact caches, and rate-limited API endpoints.

Detailed Subtopics:
• Functional vs non-functional requirements (SLAs, SLOs, SLIs).
• Latency (P50, P95, P99), throughput (RPS/QPS), concurrency, and saturation.
• Horizontal vs vertical scaling; stateless services vs stateful model workers.
• Load balancing algorithms (Round Robin, Least Connections, Consistent Hashing for KV-cache prefix affinity).
• Caching strategies: Cache-aside, Write-through, Write-back; Eviction policies (LRU, LFU, ARC).
• Relational vs NoSQL trade-offs; Message queues (Kafka/RabbitMQ) for decoupled ingestion.
• Idempotency keys, circuit breakers, exponential backoff with jitter, backpressure.
🛠️ Hands-on Exercise: Implement a token-bucket rate limiter in Python using Redis and assert that burst traffic exceeding 50 RPS receives HTTP 429 while healthy traffic proceeds.
Phase B • P0 Essential

Networking & Linux Systems Internals

Duration: 2 Weeks • ~35 Hours

Why it matters: AI inference and distributed training are bounded by operating system throughput and network interfaces. Knowing how Linux allocates pages, switches process contexts, and handles sockets is mandatory to diagnose latency spikes.

Detailed Subtopics:
• Linux process model, threads, fork(), copy-on-write, CPU context switching.
• Virtual memory, page tables, page faults, huge pages (transparent huge pages in GPU runtimes).
• File descriptors, standard I/O, epoll vs select in asynchronous servers (uvloop/FastAPI).
• Sockets, TCP 3-way handshake, TCP slow start, TIME_WAIT states, HTTP/1.1 keep-alive vs HTTP/2 multiplexing vs gRPC.
• Linux profiling tools: top, htop, vmstat, iostat, strace, netstat, perf.
🛠️ Hands-on Exercise: Run strace -c on a Python FastAPI model endpoint under a 100-request load test to inspect the number and latency of syscalls (read, write, futex, epoll_wait).
Phase C • P0 Essential

Distributed Systems Fundamentals

Duration: 4 Weeks • ~60 Hours

Why it matters: Modern AI models do not fit on a single machine or GPU. Understanding distributed consensus, network partitions, split-brain scenarios, and replication is the hallmark of a true infrastructure engineer.

Detailed Subtopics:
• Network failure models: asynchronous networks, partial failures, network partitions.
• Consistency models: Strong consistency (Linearizability), Sequential, Eventual consistency.
• The CAP theorem: why consistency must be traded against availability during network partitions.
• Consensus algorithms: Leader-follower replication, Quorums (W + R > N), Raft algorithm (leader election, log replication, safety).
• Distributed transactions: Two-Phase Commit (2PC) limitations vs Saga pattern.
• Delivery guarantees: At-most-once, At-least-once, and handling idempotency via unique request tokens.
• Backpressure and avoiding cascading failure: Jitter, dead letter queues (DLQs), bulkhead pattern.
🛠️ Hands-on Exercise: Build a 3-node in-memory leader-follower key-value store in Python where followers poll logs from a leader; simulate node disconnection and observe how the quorum handles writes.
Phase D • P1 Practical

Databases, Storage & Data Systems

Duration: 3 Weeks • ~40 Hours

Why it matters: AI systems store different assets with drastically different latency and throughput requirements: structured metadata (PostgreSQL), high-speed state/cache (Redis), multi-gigabyte model checkpoints (S3/MinIO), and embeddings (Vector DBs).

Detailed Subtopics:
• Relational databases (PostgreSQL): B+ Tree indexing, EXPLAIN ANALYZE, connection pooling (PgBouncer).
• Distributed key-value caches (Redis): Data structures, pub/sub, TTL eviction, Redis Cluster sharding.
• Object storage (AWS S3 / MinIO): Immutable blobs, multipart uploads, byte-range requests for checkpoint loading.
• Message streams (Apache Kafka): Partitions, offsets, consumer groups, write-ahead logging.
• Vector databases & Approximate Nearest Neighbors (ANN): HNSW graph traversal, IVF-PQ quantization (Qdrant, Chroma).
🛠️ Hands-on Exercise: Spin up local MinIO and Qdrant in Docker; write a Python script that uploads a 50MB dummy model checkpoint to MinIO and indexes 10,000 vector embeddings into Qdrant with HNSW.
Phase E • P1 Practical

Containers, Kubernetes & Workload Orchestration

Duration: 3 Weeks • ~45 Hours

Why it matters: Production AI services run on Kubernetes. You must understand how Pods are scheduled on GPU nodes, how resource limits work, and how autoscaling operates under queue depth spikes.

Detailed Subtopics:
• Docker architecture: Linux cgroups, namespaces, image layer caching, multi-stage builds.
• Kubernetes core primitives: Pods, Deployments, Services (ClusterIP vs NodePort), ConfigMaps, Secrets.
• Resource scheduling: CPU/Memory requests vs limits; OOMKilled triggers.
• Health probes: Liveness, Readiness, and Startup probes (critical for 2-minute LLM weight loading).
• GPU scheduling: NVIDIA Container Toolkit, nvidia.com/gpu resource limits, taints and tolerations for GPU node pools.
• Local testing without cloud bills: Using kind (Kubernetes in Docker) or minikube on your laptop.
🛠️ Hands-on Exercise: Deploy a local FastAPI service in a kind cluster with 3 replicas, readiness probe delay for simulated model loading, and Horizontal Pod Autoscaler (HPA) simulating load.
Phase F • P1 Practical

Feature Stores, Ingestion Pipelines & Model Artifact Registries

Duration: 2 Weeks • ~30 Hours

Why it matters: Machine learning models require real-time feature retrieval with point-in-time correctness to prevent train-serve skew. Model weight artifacts (multi-gigabyte safetensors) need versioned, immutable storage with fast streaming retrieval.

Detailed Subtopics:
• Online vs Offline Feature Stores (Redis/Cassandra for <10ms online inference; Snowflake/Parquet for offline training).
• Train-serve skew and historical point-in-time joins.
• Feast / Hopsworks architecture: feature definitions, registry, online sync jobs.
• Batch & stream feature ingestion (Kafka topics → streaming aggregations → key-value cache).
• Model Artifact Storage: MLflow / Hugging Face Hub / S3, safetensors vs pickle (security & zero-copy mmap loading).
• Model lineage, semantic versioning, and canary deployment tagging.
🛠️ Hands-on Exercise: Set up a local Feast feature repository backed by SQLite (offline) and Redis (online); write a feature retrieval function that serves fresh features with <5ms latency and verifies point-in-time correctness.
Phases G, H & I • P0 The AI Infra Money Zone

Model Serving, GPU Hardware & LLM Inference Infrastructure

Duration: 6 Weeks • ~90 Hours

Why it matters: This is where general software engineers get filtered out. Here you master why LLM inference is memory-bandwidth bound, how KV-cache paging eliminates memory fragmentation, and how dynamic continuous batching maximizes GPU utilization.

Detailed Subtopics:
• GPU Architecture: Streaming Multiprocessors (SMs), Tensor Cores, HBM vs SRAM (on-chip cache).
• Prefill (compute-bound) vs Decode (memory-bandwidth-bound) phases.
• KV-Cache memory consumption math: $2 \times 2 \times \text{layers} \times \text{heads} \times \text{dim} \times \text{bytes}$.
• Continuous Batching (iteration-level scheduling) vs Static batching.
• PagedAttention (vLLM architecture) — physical block tables and eliminating external fragmentation.
• SGLang & RadixAttention — KV-cache prefix tree sharing across multi-turn chats.
• Quantization: FP16 vs BF16 vs FP8 (E4M3) vs INT4 (AWQ).
• Serving engines compared: FastAPI vs Triton Inference Server vs vLLM vs Hugging Face TGI vs Ray Serve.
🛠️ Hands-on Exercise (RTX 2050 4GB Compatible): Run a quantized 1.5B or 3B small open-weight model (e.g. Qwen-2.5-1.5B or SmolLM2) locally on your 4GB laptop GPU using Ollama or vLLM; profile memory footprint before and after token generation and measure TTFT vs ITL.
Phases J, K & L • P1 Production Engineering

Distributed Training, Observability & Multi-Tenant Security

Duration: 4 Weeks • ~55 Hours

Why it matters: Shipping to production requires complete observability (Prometheus/Grafana), automated health recovery, and multi-tenant isolation.

Detailed Subtopics:
• Distributed training strategies: Data Parallelism (DDP/FSDP), ZeRO 1/2/3, Tensor Parallelism.
• NCCL collectives: Ring All-Reduce, Reduce-Scatter, All-Gather.
• OpenTelemetry distributed tracing: Tracing requests from API Gateway → Queue → GPU Worker → DB.
• GPU metrics via DCGM: SM utilization, memory bandwidth percentage, PCIe throughput, thermal throttles.
• Multi-tenancy: API key quotas, tier-based rate limiting, prompt sanitization, network isolation.
🛠️ Hands-on Exercise: Instrument a Python inference worker with Prometheus metrics (inference_latency_seconds_bucket, kv_cache_usage_percent) and configure a local Grafana dashboard.
