Part 1 • Executive Summary

The Reality of Modern AI Systems
01 What AI Infra Actually Is
AI Infrastructure is Systems & High-Performance Distributed Computing applied to neural execution. It is NOT training models or doing exploratory Jupyter data analysis. It is ensuring multi-terabyte weights stay in GPU SRAM/HBM without starving, clusters communicate over NCCL without deadlocks, and inference requests serve within strict P99 latency budgets.
02 Most Realistic Initial Role
AI Platform / Inference Serving Engineer (Stage 1). Directly designing inference APIs, dynamic batching, asynchronous worker queues, and automated evaluation harnesses. Once inside an engineering team with production traffic, you leverage company-funded H100 clusters to transition into deep Distributed Training & GPU Kernel optimization (Stage 2).
03 The 3 Non-Negotiable Skills
1. Asynchronous Concurrency & Queuing: Designing resilient multi-worker producer-consumer pipelines.
2. Memory-Hierarchy Intuition: Knowing why KV-cache causes OOMs, why decode is memory-bound, and how to avoid cache thrashing.
3. Distributed Fault Tolerance: Handling partial network failures, timeouts, and idempotent retries.
⚠️ Major Risk & Misconception to Avoid:
Do not mistake "Calling the OpenAI or Anthropic API via LangChain" for AI Infrastructure Engineering. In an infrastructure system design interview, you will be asked: "How does vLLM schedule continuous batches without blocking the event loop?", "What happens to the KV cache block table during a client TCP disconnect?", "How do you size GPU cluster nodes for 10,000 QPS with p99 < 25ms?". This curriculum trains you to answer those exact questions with whiteboard derivations.

Part 3 • Prerequisite Assessment & Diagnostic Test

Benchmark Your Current Foundation
✅ What You Already Bring
  • • Python & ML Basics: Understand tensor shapes, supervised learning, and basic neural forward passes.
  • • API & Backend Intuition: FastAPI endpoints, JSON serialization, HTTP status codes, Docker containerization.
  • • Catalog & Data Quality Mindset: Testing edge cases, data sanitization, verifying structured outputs.
⚡ What Must Be Strengthened
  • • Linux OS Internals: Processes vs threads, virtual memory, paging, file descriptors, non-blocking sockets.
  • • Distributed Systems Fundamentals: Replication, leader election, idempotent retries, backpressure, circuit breakers.
  • • GPU Hardware Memory Hierarchy: SRAM vs L2 vs HBM, memory bandwidth bottlenecks, KV-cache sizing.
🧪 5-Question Self-Diagnostic Test
Answer these without searching. If you can explain 3 or more with trade-offs, you can skip Phase A and start directly in Phase B:
Q1 (Networking & OS): In a Python FastAPI server running behind Gunicorn with 4 workers, what happens if an endpoint calls a blocking synchronous function time.sleep(10)? How does asyncio event loop differ from multi-process worker pools?
Q2 (Distributed Systems): Why is "exactly-once" message processing considered theoretically impossible over an unreliable network, and how do systems like Kafka achieve effective exactly-once semantics using idempotency keys and transactional offsets?
Q3 (Storage & Databases): What is the difference between an Append-Only Log (LSM-tree) and a B+ Tree, and why do high-throughput write systems (like metric collectors or vector index logs) prefer LSM trees?
Q4 (LLM Hardware): Why is generating tokens from a 70B parameter model in FP16 fundamentally memory-bandwidth bound rather than compute-bound when serving a single request?
Q5 (Reliability & Evals): What is the "Retry Storm" problem, and how do jittered exponential backoff and circuit breakers prevent downstream inference services from collapsing?

Part 4 • The Finish Line: Observable Engineering Competencies

Graduated Benchmark Levels
Level 1: Beginner
• Build a production-grade FastAPI model inference service with Docker, structured logging, health checks, and P95 latency timers.
• Design an asynchronous job queue using Redis & Celery with status polling and idempotent retry mechanisms.
• Set up Prometheus metrics and Grafana dashboards tracking QPS, error rate, and queue depth.
Level 2: Intermediate
• Calculate exact KV-cache sizing, memory bandwidth limits, and tokens/sec throughput for any transformer model.
• Implement dynamic request batching to group individual inference requests into batched tensor operations.
• Deploy and benchmark local inference engines (vLLM / Ollama) comparing FP16 vs INT4 quantization and measuring Time-To-First-Token (TTFT) vs Inter-Token Latency (ITL).
Level 3: Advanced
• Defend a complete multi-tenant LLM serving architecture on a whiteboard, explaining PagedAttention, continuous batching, rate limiting, and disaggregated prefill/decode.
• Design a fault-tolerant distributed training platform with spot instance recovery, asynchronous checkpointing, and NCCL communication.
• Formulate an interactive capacity plan sizing GPU clusters, network fabrics, and storage bandwidth for 500+ QPS workloads.
