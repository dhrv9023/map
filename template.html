THE "HOW TO LEARN" PROTOCOL: DO NOT READ DOCUMENTATION COVER-TO-COVER!

The Biggest Trap for Self-Taught Engineers is "Documentation Paralysis": Opening official Python, FastAPI, or vLLM docs and attempting to read hundreds of pages like a novel. You get exhausted by Chapter 3 and quit. Documentation is an index dictionary, not a book! Nobody reads the entire dictionary from A to Z before speaking English.
1. The 45-Minute Hard Timebox Never spend more than 30–45 minutes reading. Read only the specific 2–3 sub-sections targeted in each module below. If the timer rings, close the docs immediately.
2. Type by Hand & Break It in REPL Never copy-paste. Open your terminal (python3, bash, or g++). Type the 5-line code snippet by hand. Change inputs. Break it intentionally to see how it fails.
3. Close the Docs & Build the Task Close all documentation browser tabs. Open VS Code and start writing the Practical Task. Reopen docs ONLY via Ctrl+F lookup when a specific test or compiler error occurs.
4. Stop Immediately When Tests Pass The exact second your unit tests pass or acceptance criteria are verified, STOP. Do not read extra chapters to "feel productive". Advance immediately to the next task.

The Beginner's 4-Step "Stuck Protocol"

  • Step 1: Pen & Paper First (5 min): Never touch the keyboard immediately. Write down a tiny sample array (e.g. [2, 7, 11, 15], target 9). Walk through how your human eyes solve it.
  • Step 2: Shameless Brute Force (10 min): Write the naive solution first! A working nested loop with O(N²) is infinitely better than staring at an empty editor. Getting test cases to pass builds immediate confidence.
  • Step 3: Spot the Bottleneck: Ask: "Which part of my brute force is slow?" Example: "I am searching for (target - x) across the array in O(N). Can I do it in O(1)?" → Hash map discovered!
  • Step 4: Refactor to C++ Optimal (15 min): Replace the slow search with the optimal data structure, check edge cases (empty array, single element, negative numbers), and submit.
